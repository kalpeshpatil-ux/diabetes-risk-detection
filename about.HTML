Project Overview & Viva Examination Guide

This project was developed for the subject Computing in Python. It combines data engineering, applied supervised machine learning, and web application development using Flask.

💡 What is the Diabetes Risk Detection System?

Diabetes mellitus is a chronic metabolic disorder characterized by elevated levels of blood glucose. Early detection enables lifestyle interventions that can delay or prevent the onset of Type 2 diabetes. This project implements a complete end-to-end Machine Learning pipeline:

1. Data Cleaning

Identifies physiologically impossible zero values in clinical variables and imputes them using column medians.

2. Algorithm Comparison

Trains and rigorously compares Logistic Regression, Decision Tree, and Random Forest on held-out test data.

3. Clinical Web App

Provides a responsive user interface with validation, risk stratification, and personalized lifestyle guidance.

📂 File Architecture & Purpose (Viva Reference)
train_model.py

The offline machine learning pipeline. It loads diabetes.csv, cleans zero-value anomalies, performs an 80/20 train-test split, trains 3 models, evaluates accuracy and confusion matrix, and exports model.pkl and model_info.json.

app.py

The Flask web server. Handles routes for the prediction form (/), model performance metrics (/performance), and about documentation (/about). Loads model.pkl to perform real-time probability inference.

templates/ (index.html, performance.html, about.html, base.html)

Jinja2 HTML templates providing a modular, consistent layout across all application pages with responsive card structures.

static/style.css

Custom CSS styling that provides modern health-tech typography, color-coded risk badges, responsive layouts, and interactive buttons.

🎓 Top Viva / Oral Examination Questions & Answers
❓ Q1: Why did you replace 0 with median for Glucose, BP, BMI, etc.?
In human physiology, a glucose level of 0 mg/dL or a blood pressure of 0 mm Hg is incompatible with life. In the Pima Indians dataset, 0 was recorded when the lab measurement was missing. If treated as numeric zero, the model would learn false correlations. We impute with the median because the median is robust to extreme outliers and skewed distributions.
❓ Q2: Why did you use 'stratify=y' during train_test_split?
The Pima dataset has class imbalance (~65% negative, ~35% positive). Setting stratify=y guarantees that both the training set (80%) and the testing set (20%) have the exact same proportion of diabetic patients, preventing sampling bias.
❓ Q3: Why did Random Forest outperform a single Decision Tree?
A single Decision Tree is prone to high variance and overfitting on training data. Random Forest is an ensemble method (bagging) that constructs multiple decision trees using bootstrap sampling and random feature subsets. Averaging predictions across trees reduces variance without increasing bias.
❓ Q4: What is the purpose of joblib in this project?
joblib is an optimized serialization library in Python. It serializes the trained scikit-learn model object into a binary .pkl file on disk. The Flask server can then load this model instantaneously without retraining from scratch on every user request.
❓ Q5: How does the model calculate risk percentage?
The model uses predict_proba(data), which outputs the posterior probability distribution for each class. We extract the probability for class 1 (diabetic outcome) and multiply by 100. If probability < 35% it is categorized as Low, 35%–65% as Moderate/Pre-diabetic, and > 65% as High.
